# Top Kong

Аренный ragdoll-мордобой с видом сверху. У бойца вместо одной руки — дубина,
вместо второй — нога. На этой ноге он и передвигается: не ходит, а прыгает
короткими микро-прыжками, подкидывая себя вверх.

Урона в игре нет вообще. Ни здоровья, ни полосок. Единственная цель — столкнуть
всех остальных с маленького круглого диска. Упал — выбыл. Кто остался — победил.

## Как запустить

1. Unity Hub → **Add** → **Add project from disk** → выбрать папку этого репозитория.
2. Открыть проект. Если Hub скажет, что версия отличается — согласиться открыть своей,
   это нормально (в `ProjectSettings/ProjectVersion.txt` записана 6000.0.32f1).
3. Нажать **Play**. Из любой сцены, хоть из пустой.

Никакой сцены открывать и ничего расставлять не нужно. Арена, свет, камера, бойцы
и интерфейс собираются кодом при старте — в проекте нет ни одного префаба и ни одного
бинарного ассета, только скрипты.

Если хочется, чтобы игра лежала в отдельной сцене (удобно: настройки видно в инспекторе
ещё до Play) — **Tools → Top Kong → Создать сцену арены**.

## Управление

| | |
|---|---|
| **W A S D** или **стрелки** | микро-прыжки в сторону движения |
| **мышь** | дубина |
| **R** | новый раунд |
| **Esc** | освободить курсор, **клик** — вернуть |

Курсор захватывается: он скрыт, и учитываются только движения мыши.

## Как это работает

**Дубина — не анимация, а физическое тело.** Мышь двигает точку прицела, а дубину
к этой точке тянет PD-регулятор. Дёрнул мышь резко — точка ушла далеко, рассогласование
выросло, сила выросла, дубина разогналась. Дальше физика сама передаёт сопернику импульс,
пропорциональный набранной скорости.

Поэтому «быстрее машешь — сильнее бьёшь» нигде отдельно не запрограммировано, это просто
следствие. И поэтому в игре нет кнопки атаки: если мышь стоит на месте, дубина висит.
Точка прицела всё время пружинит обратно в нейтраль, так что подвести её и держать
не получится — махать надо непрерывно.

Полоска **СИЛА ЗАМАХА** внизу экрана — это буквально текущая скорость дубины.
Засечка на ней показывает порог, ниже которого касание вообще не считается ударом.

**Бойцы — активные ragdoll'ы.** Семь физических тел на суставах. Вертикально их держит
контроллер баланса: рейкаст вниз плюс пружина под тазом плюс момент, доворачивающий тело
к «вверх». От сильного удара приводы суставов почти мгновенно падают в ноль — боец обмякает,
шатается и вполне может улететь с арены. Обратно в стойку он собирается уже медленно.

**Боты играют теми же мышцами.** У бота нет ни телепортов, ни бесплатных ударов: он так же
прыгает на одной руке-ноге и так же разгоняет дубину, просто вместо мыши ему работает
синусоида. И так же может улететь от собственного замаха у края.

## Настройка

Всё, что можно крутить, лежит в одном месте — компонент **GameBootstrap** на объекте
`TopKong` в Hierarchy. Значения читаются каждый кадр, поэтому менять их можно
**прямо во время Play** и сразу видеть результат.

Если что-то ощущается не так, начинать стоит отсюда:

| Ощущение | Что крутить |
|---|---|
| Прыжки вялые или наоборот скачешь как мяч | `hopUp`, `hopAccel`, `hopInterval`, `maxRunSpeed` |
| Дубина тяжёлая и не поспевает за мышью | `clubKP`, `clubMaxAccel`, `mouseSensitivity` |
| Удары не сносят / сносят слишком легко | `minKnockback`, `maxKnockback`, `knockUpBias` |
| Боец слишком легко падает сам | `uprightSpring`, `uprightDamper`, `suspensionSpring` |
| Хочется больше тряпичности | уменьшить `driveSpringMul` |
| Боты слишком злые или слишком тупые | `botSkill`, `botSwingRange`, `botReaction` |
| Мало/много соперников | `botCount` (перезапустить раунд по **R**) |

## Render pipeline

Проект открывается на Built-in — это то, что Unity настраивает сама, и на этом он
гарантированно запускается без единого лишнего файла.

Игра одинаково работает и на URP: `MaterialFactory` подбирает шейдер в рантайме.
Если хочется URP:

1. Window → Package Manager → Unity Registry → **Universal RP** → Install
2. **Tools → Top Kong → Включить URP**

Пункт меню создаст pipeline-ассет и пропишет его в Graphics Settings. Если не получится —
он честно скажет в консоли, что сделать руками.

## Если что-то пошло не так

**Всё розовое.** Не нашёлся шейдер. Смотри консоль — `MaterialFactory` пишет об этом
предупреждение. Обычно значит, что пакет URP установлен, но pipeline-ассет не назначен:
Tools → Top Kong → Включить URP.

**Всё розовое, но только в собранном билде.** Материалы создаются в рантайме через
`Shader.Find`, а шейдеры, на которые в проекте нет ни одной ссылки, при сборке
выбрасываются. В редакторе этого не видно. Лечится добавлением нужного Lit-шейдера
в Project Settings → Graphics → **Always Included Shaders**. Для игры в редакторе —
не проблема.

**Ошибки про `Input.GetKey` и Input System.** Проект переключён на новый Input System.
Код это переживает (`UnityCompat.cs` компилируется в нужную ветку), но если ошибки всё же
есть — Project Settings → Player → Active Input Handling → **Both**.

**Бойцы дрожат или расползаются.** Уменьшить `fixedTimestep` (например, до 1/90)
и/или поднять `solverIterations`.

**Игра запускается дважды.** Объект `TopKong` уже лежит в сцене, и хук поднял второй.
Такого быть не должно — `GameBootstrap` это отслеживает, — но если случилось, просто
удали объект из сцены: игра поднимется сама.
